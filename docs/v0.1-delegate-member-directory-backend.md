## Exact frontend read contract

**GET `/api/v1/communities/{community_slug}/memberships`**

For the current product, use `community_slug=irm`. The backend resolves the slug and confines both records and cursor lookup to that community. Foreign communities used in tests establish isolation; this does not add multi-community product UI.

Authentication uses the existing database-backed HTTP-only session cookie. The caller must have an **ACTIVE membership with role DELEGATE in the requested community**. Members, Moderators (even with all current grants), guests, inactive Delegates, and Delegates of another community do not qualify. Authority is checked on every request.

| Query parameter | Type | Default | Rules |
| --- | --- | --- | --- |
| `status` | Optional, case-sensitive enum string | Omitted: all statuses | `PENDING`, `ACTIVE`, `REJECTED`, `REMOVED`, `BANNED`. Omit for All; do not send `ALL`, an empty string, `null`, or a lowercase value. |
| `limit` | Integer | `20` | Inclusive range `1` through `100`. |
| `after` | Optional UUID string | Omitted: first page | Pass the previous response's non-null `next_cursor` unchanged. Omit for first page. |

Examples:

```text
GET /api/v1/communities/irm/memberships
GET /api/v1/communities/irm/memberships?status=BANNED&limit=20
GET /api/v1/communities/irm/memberships?status=BANNED&limit=20&after=00000000-0000-0000-0000-000000000008
```

Success is **200**, JSON, with `Cache-Control: private, no-store`.

Representative terminal BANNED response, using a real username from the test fixture:

```json
{
  "items": [
    {
      "id": "00000000-0000-0000-0000-000000000008",
      "username": "actual_banned",
      "status": "BANNED",
      "role": "MEMBER",
      "created_at": "2026-01-01T00:00:00Z",
      "updated_at": "2026-01-01T00:00:00Z"
    }
  ],
  "next_cursor": null
}
```

A non-terminal response has `next_cursor` equal to the UUID of its last returned item. An empty result is exactly `{"items": [], "next_cursor": null}`. There is no total count.

`id` identifies the **membership**, and is the target ID for the existing management mutations. `username` is read from the joined User row, not synthesized from a UUID or private identity field. Roles are `MEMBER`, `MODERATOR`, or `DELEGATE`. Timestamps are ISO 8601 datetime strings. Each item contains only `id`, `username`, `status`, `role`, `created_at`, and `updated_at`.

No CNE, email, first/family names, account user ID, password hash, session ID, token/hash, expiry/revocation fields, grants, or audit records are returned. The directory read creates no management event.

## Pagination and refresh semantics

The order is `created_at DESC, id DESC`; UUID breaks timestamp ties. SQL selects only the six item fields, joins User once, and reads at most `limit + 1` records to detect another page. Cursor lookup selects only anchor ID, timestamp and status in the requested community.

A syntactically valid cursor must refer to a membership in that community. For a filtered request, its **current** status must match `status`. A different-community or unknown UUID returns 400. A valid membership with a mismatching status also returns 400. Cursor syntax errors return 422.

Pagination is a live keyset view, not a frozen snapshot. A newer insertion does not shift the continuation into duplicate older records. Changing the anchor's status preserves an unfiltered cursor, but invalidates a cursor for its former status. After Remove/Ban/Unban, reset the cursor and refresh the active filter; on cursor 400, refresh from the first page. Reset the cursor when changing filters. Concurrent changes may affect later pages; no snapshot consistency is promised.

## Exact handled error statuses

Handled directory errors also include `Cache-Control: private, no-store`.

| Status | Trigger | Body |
| --- | --- | --- |
| `401` | Missing, invalid, expired, or revoked session; missing account | `{"detail":"Not authenticated"}` |
| `403` | No ACTIVE membership in requested community, or role is not DELEGATE | `{"detail":"Not enough permissions"}` |
| `404` | Authenticated request for unknown community | `{"detail":"Community not found"}` |
| `400` | Unknown or foreign-community cursor UUID | `{"detail":"Invalid pagination cursor"}` |
| `400` | Anchor status differs from requested filter | `{"detail":"Pagination cursor does not match the requested status filter"}` |
| `422` | Invalid status, malformed cursor UUID, non-integer limit, or limit outside 1–100 | Standard FastAPI validation body with `detail` array and query field location |

Authentication and Delegate dependencies run before directory cursor lookup. Forbidden callers cannot probe membership existence using a valid UUID. This read has no normal 409 response. Unexpected server/database errors can produce 500; successful verification of a production deployment is not claimed.
