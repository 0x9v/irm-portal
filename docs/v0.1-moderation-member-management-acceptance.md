## Root causes and corrections

**Frontend workspace:** the original error explicitly reports node_modules linking outside Turbopack's root. The runner now copies installed dependencies with `cp -a --reflink=auto`: reflinks or independent copies, never hard links. It counts linked content and checks free space with a 100 MiB margin before copying; repeated directory links/loops and failed copies fail clearly. Internal executable/package links are remapped into the owned copy; external links are materialized into independent files. A final check refuses links escaping that copy. Source `.env*`, output and caches remain excluded. No Next configuration, build command, validation, dependencies, or lockfile was changed.

A fresh intermediate experiment dereferenced executable links too; `npm run build` exposed `Cannot find module '../server/require-hook'` from `.bin/next`. That implementation was corrected. A focused regression now proves executable links resolve inside the copied package, including originally absolute links. Copy tests also prove changes to copied regular/externally linked files do not change their sources and insufficient space refuses before destination creation.

**Failure evidence:** pytest commands use `--tb=short`. The worker additionally records failed reports with the exact `setup`, `call`, or `teardown` phase, test ID, and sanitized traceback in `<stage>-failures.json`. A real nested pytest run verifies all three phases. Worker initialization failures record `worker_setup`; parent stage failures retain a bounded traceback and detail. Cleanup reports its actual error message and current schema. Known passwords, database URLs, cookie/session headers, manifest paths, ownership markers, and labeled password/nonce/token values are redacted. Private manifests are never copied into public reports.

**PostgreSQL:** shared suites still attach only after verifying database, role, exclusive search_path, migrated layout and ownership marker. Concurrency/lifecycle tests use separately journaled schemas, standard schema-local Alembic, and engine-local checkout guards. The original 76 passes plus seven errors, followed by an older 76-pass rerun, is consistent with seven teardown failures; however the original logs do not preserve phase tracebacks, so this cannot be certified retroactively.
