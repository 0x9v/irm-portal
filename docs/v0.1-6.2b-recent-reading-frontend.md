# Task 6.2B — Recently Opened Documents and PDF Position Frontend

## Implemented

- The approved PDF reader sends one authenticated `reading/open` request per document visit and account. It does not send opens for images or documents whose metadata is not approved. The PDF becomes visible without waiting for this request.
- After PDF.js provides the page count, the reader restores the saved page clamped to the available range. Page updates use a 500 ms debounce and a serialized queue so an earlier in-flight update is followed by the newest page. `pagehide` and hidden-tab transitions attempt a `keepalive` flush.
- Reading API failures leave the PDF usable and show restrained restore/save feedback. Account changes remount the reader under a new user key; pending requests are aborted.
- Added an authenticated Recently Opened page backed by the bounded cursor endpoint. It includes actual document/module/type/source data, last-open time and page, reader links, loading/empty/error/retry/load-more states, request cancellation, and user ownership checks. It does not require ACTIVE membership or use local storage.
- Added one Recently Opened entry point to the Modules page.
