GET `/api/v1/communities/{community_slug}/memberships` uses existing authenticated HTTP-only session requests. Only an ACTIVE Delegate of the requested community qualifies. Current frontend authority is verified for IRM only and cannot authorize another slug.

| Query | Exact contract | Frontend |
| --- | --- | --- |
| `status` | Optional case-sensitive `ACTIVE`, `PENDING`, `REJECTED`, `REMOVED`, `BANNED`; omit for all | All omits the parameter; other filters use exact enum values |
| `limit` | Integer, default 20, inclusive 1–100 | Fixed 20 per request |
| `after` | Optional UUID; previous non-null `next_cursor` unchanged | Omitted for initial reads, refresh and changed filters |

Response: `{ items, next_cursor }`. Each item contains exactly membership `id`, actual `username`, `status`, `role`, `created_at`, `updated_at`. Roles: MEMBER, MODERATOR, DELEGATE. Timestamps are datetime strings. Terminal/empty cursor is null; no total count exists. UUIDs identify mutations and rows internally, never identity labels.

Order is `created_at DESC, id DESC`. A cursor must resolve in the requested community and, when filtered, match the anchor's current status. Pagination is live, not a snapshot. Unknown/foreign cursor or mismatched filter returns 400; malformed UUID, invalid enum or limit returns 422. Authentication failure is 401, insufficient authority 403, unknown community 404. The read has no normal 409. Handled reads use `Cache-Control: private, no-store`.

Unban is bodyless DELETE `/api/v1/communities/{community_slug}/memberships/{membership_id}/ban`, empty 204. Backend transitions BANNED to REMOVED and clears old grants; it does not activate or approve membership. Existing mutation 401/403/404/409 behavior is preserved.

## Behavior and async safety

- Active is the default; All/Active/Pending/Rejected/Removed/Banned are available. Displays actual @username, status and role. Delegate targets are protected. ACTIVE/PENDING/REJECTED offer Remove/Ban, REMOVED offers Ban, BANNED offers Unban; unknown roles/states expose no actions.
- Confirmed ACTIVE IRM Delegate gating applies before any directory read and at desktop/mobile navigation. Guests, Members, Moderators, loading/refresh/logout states, errors and unverified membership fail closed.
- Account, membership, community and filter changes replace protected scopes. Layout cleanup aborts reads and invalidates completions; authority loss clears rows/cursors and unmounts dialogs. A 401/403 read or action triggers existing auth/membership revalidation.
- Filter changes clear rows, cursors, pagination errors and dialogs immediately. Refresh aborts/invalidate pagination and resets to the first page. Each read captures its filter/cursor, signal and revision. Obsolete results cannot refill a refreshed directory. Load More failure retains loaded rows, offers retry and deduplicates by membership ID.
- Initial loading, empty (including Banned), read retry, refresh and Load More states are visible. A 400 explains an invalidated cursor and offers first-page refresh; directory 404 explains unavailability.
- Unban confirmation names the username, focuses Cancel, contains keyboard focus, supports Escape while idle, restores focus and disables duplicate/pending submission. Copy explains fresh application, REMOVED, and no restored membership/management permissions. Cancel sends no request.
- Successful 204 causes an authoritative first-page read for the selected filter. Banned drops the row only through that read; All renders backend REMOVED if returned. No local ACTIVE assignment occurs.
- Mutation 404 explains unavailable membership and refreshes; 409 explains state conflict and refreshes. Network/500 leaves outcome unconfirmed, offers Refresh and check, and permits explicit user retry. There are no automatic mutation retries. Aborted/stale client work does not undo a server mutation.
