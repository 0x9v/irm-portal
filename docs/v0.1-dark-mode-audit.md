## Executive Summary

This document provides the complete, source-backed visual audit and engineering specification for adding Dark Mode to the IRM platform frontend (`/home/yasso/irm-platform/frontend`).

In accordance with product directives:
- The approved **violet visual identity** and **left sidebar architecture** are strictly preserved.
- The existing light-mode appearance and functional contracts remain 100% unchanged.
- The dark mode aesthetic uses a **restrained dark aubergine palette** (`#130D1E` canvas, `#1C142A` surface, `#261C3B` secondary surface) rather than pure pitch-black or neon magenta.
- The PDF reader, uploaded media, and community stickers maintain authentic visual rendering without blanket canvas inversion.
- Theme switching supports **Light**, **Dark**, and **System** preference, stored in `localStorage`, decoupled from authentication, and rendered without flash-of-unthemed-content (FOUT) or hydration mismatch.
- No external libraries (such as `next-themes`) are introduced, keeping the bundle lightweight and native to Next.js 16 and Tailwind CSS v4.

## 1. Current Architecture and Theme Readiness

### 1.1 Existing CSS Architecture (`globals.css`)
- **Framework:** Next.js 16.3.6 (React 19.2.8) with Tailwind CSS v4 (`@tailwindcss/postcss ^4`).
- **Token Mechanism:** `frontend/src/app/globals.css` uses the Tailwind v4 `@theme inline` block mapped to 35 root CSS custom properties (`:root { --page: #FAF8FC; ... }`).
- **Readiness Rating: High (Foundation is already token-driven).**
  - The application already uses semantic class abstractions such as `bg-page`, `bg-surface`, `bg-surface-secondary`, `bg-surface-aubergine`, `text-text`, `text-text-muted`, `text-text-subtle`, `border-border`, `border-control-border`, `bg-accent`, `text-on-accent`, `outline-focus`, etc.
  - Component utilities (`.btn-primary`, `.btn-secondary`, `.btn-destructive`, `.btn-subtle`, `.badge-success`, `.badge-warning`, `.badge-error`, `.badge-info`, `.input-base`) are already defined in `globals.css` using these tokens.

### 1.2 Gaps in Current Styling Foundation
1. **No Dark Theme Selector:** There is currently no `:root[data-theme="dark"]` or `.dark` class block in `globals.css`. All CSS variables have only light-theme values.
2. **Missing `color-scheme` Declaration:** `:root` does not specify `color-scheme: light dark;`, causing native browser form controls (scrollbars, `<select>` dropdowns, file pickers, date pickers) to render light controls even when dark styling is applied.
3. **Hardcoded Color Classes in Component Code:**
   - Isolated pages (e.g. `membership/page.tsx`, `membership/review/page.tsx`, `membership/staff/page.tsx`, `pending/page.tsx`, `discussion/page.tsx`) bypassed semantic tokens in favor of raw Tailwind classes (`bg-green-50 text-green-800`, `bg-amber-50 text-amber-800`, `bg-red-50 text-red-800`, `bg-[#EAE6F2]`, `bg-[#FAF5FF]`).
   - `SidebarNav.tsx` has hardcoded hex colors on the account footer (`bg-[#FCFBFD]` and `hover:bg-[#F8F5FB]`).
   - `DocumentReader.tsx` has hardcoded fallback/error container classes (`bg-white border-gray-200 text-gray-600 text-blue-600`) and hardcoded viewport canvas background (`bg-[#EAE6F2]`).
4. **Hydration & Flash Avoidance:**
   - `frontend/src/app/layout.tsx` defines `<html lang="en">` without `suppressHydrationWarning` and without an inline initialization script.
   - Without an inline `<script>` in `<head>`, reading theme preference in client-side `useEffect` causes a bright white flash on initial reload.

## 4. Contrast Calculations & WCAG AA Verification

Contrast ratios were mathematically computed using the official W3C WCAG 2.1 relative luminance formula:
$$L = 0.2126 \times R + 0.7152 \times G + 0.0722 \times B$$
where color components are linearized:
$$C_{\text{linear}} = \begin{cases} \frac{C}{12.92} & \text{if } C \le 0.04045 \\ \left(\frac{C + 0.055}{1.055}\right)^{2.4} & \text{if } C > 0.04045 \end{cases}$$
and the contrast ratio is $\frac{L_1 + 0.05}{L_2 + 0.05}$ ($L_1 > L_2$).

### Target Criteria:
- **WCAG AA Normal Text:** Minimum **4.5:1**
- **WCAG AA Large Text / UI Components:** Minimum **3.0:1**
- **WCAG AAA Normal Text (Enhanced):** Minimum **7.0:1**

## 5. Theme Initialization and Preference Strategy

### 5.1 Three-Way Preference Model
The system supports three user-selectable states:
1. `light`: Forces light theme (`data-theme="light"`, no `.dark` class).
2. `dark`: Forces dark theme (`data-theme="dark"`, adds `.dark` class).
3. `system`: (Default) Automatically follows the operating system setting via `window.matchMedia('(prefers-color-scheme: dark)')`.

### 5.2 Storage Contract
- **Storage Location:** Client `localStorage`.
- **Storage Key:** `irm-theme`
- **Permitted Values:** `'light' | 'dark' | 'system'`
- **Default Value:** `'system'` (when key is unset, empty, or contains unknown/corrupted data).
- **Decoupling from Authentication:** The theme preference is purely a device/browser setting. It is **never** sent to backend auth APIs, never stored in session cookies, and **must never be wiped or mutated on user logout**.
- **Resilience:** If `localStorage` is disabled or throws a `SecurityError` (e.g., Safari Private Browsing with strict storage blocking), the system falls back gracefully to `system` in memory without throwing unhandled exceptions.

### 5.3 Flash of Unthemed Content (FOUT) & Hydration Safety
To prevent a bright white flash on initial load while preventing React hydration mismatches:

1. **Inline Pre-Hydration Script:**  
   An inline, blocking `<script>` is placed in the `<head>` of `frontend/src/app/layout.tsx`. Because it executes before CSS rendering and DOM painting, the `<html>` element receives the correct `data-theme` attribute and `dark` class before the first frame is rendered.
   ```html
   <script>
     (function() {
       try {
         var storageKey = 'irm-theme';
         var pref = localStorage.getItem(storageKey);
         var mql = window.matchMedia('(prefers-color-scheme: dark)');
         var isDark = pref === 'dark' || (pref !== 'light' && mql.matches);
         var root = document.documentElement;
         root.setAttribute('data-theme', isDark ? 'dark' : 'light');
         if (isDark) {
           root.classList.add('dark');
         } else {
           root.classList.remove('dark');
         }
         root.style.colorScheme = isDark ? 'dark' : 'light';
       } catch (e) {}
     })();
   </script>
   ```

2. **React Hydration Suppression:**  
   Add `suppressHydrationWarning` to `<html lang="en">` in `frontend/src/app/layout.tsx`. This informs React 19 that `data-theme`, `class`, and `style` attributes on `<html>` may be modified by the pre-hydration script, preventing hydration mismatch warnings in the console.

3. **No External Library Overhead:**  
   No `next-themes` dependency is needed. A lightweight `ThemeContext` (or hook) manages client state, registers a listener on `window.matchMedia('(prefers-color-scheme: dark)')` to handle live OS theme transitions when in `system` mode, and provides an update function to toggle preferences.

### 5.4 Content Security Policy (CSP) Compatibility
- Repository inspection of `backend/app/main.py` and `frontend/src/app/layout.tsx` confirms no restrictive CSP header currently forbids inline scripts.
- If a strict CSP is deployed in the future, the inline script can be given a cryptographic SHA-256 hash or nonce.

### 5.5 Selector UI Placement
- **Desktop Viewport (>= 1024px):**
  - Integrated into **Region 3 of `SidebarNav.tsx`**, positioned immediately above the Logout button.
  - Formatted as a sleek, compact 3-way segmented control (Sun icon for Light, Moon icon for Dark, Monitor icon for System).
  - ARIA attributes: `role="radiogroup"` with `aria-label="Theme preference"`, each button with `role="radio"` and `aria-checked="true|false"`.
- **Mobile Viewport (< 1024px):**
  - Integrated into the expandable `#mobile-navigation` drawer in `MobileHeader.tsx`, placed in the user settings section alongside logout.
  - Fully reachable with a 44x44px minimum touch target.

## 6. Special-Component Handling

### 6.1 PDF Document Reader (`DocumentReader.tsx`)
- **Core Requirement:** Darken the reader shell; **never invert the PDF canvas**.
- **Technical Invariants:**
  1. **Do not modify PDF.js rendering canvas:** The `<canvas>` generated by PDF.js must render with natural document colors. Inverting the canvas destroys diagrams, architectural blueprints, charts, and dark-themed slides.
  2. **Page Backing Wrapper:** The element wrapping the canvas (currently line 652 `bg-surface`) must be explicitly set to `#FFFFFF` (`bg-white` or dedicated PDF paper background) with a subtle drop shadow (`shadow-md`). Transparent PDFs will otherwise display the dark container background through the page, making black text invisible.
  3. **Reader Viewport Well:** Replace hardcoded `bg-[#EAE6F2]` (lines 648, 703) with a deep neutral well (`#161022` or `bg-[#130D1E]`). This provides clear edge definition for the white PDF page without blinding the user.
  4. **Reader Toolbar:** Uses `bg-surface-secondary border-b border-border text-text`. Zoom in/out, page navigation buttons, and download buttons use `btn-secondary` or `btn-subtle`.
  5. **Text Selection Layer:** Do not alter text-layer coordinates, CSS transforms, or font metrics. The native browser selection highlight (`::selection`) will naturally use `--accent` or OS selection color.

### 6.2 Images and Document Previews
- **Document Previews:** Thumbnail previews and iframe preview frames (e.g. `frontend/src/app/communities/irm/documents/pending/page.tsx` line 361) must replace `bg-[#EAE6F2]` with `bg-surface-secondary border border-border`.
- **Images:** Uploaded member avatars, module diagrams, and preview images must retain 100% color fidelity (no CSS invert/filter).

### 6.3 Stickers and Reactions
- **Sticker Vectors (`StickerAsset.tsx`):**
  - Inspection of SVG definitions (pepe, cat, blob, doge, coffee, duck) confirms that all sticker assets contain explicit solid vector fills (`#FFD84D`, `#4CAF50`, `#FF9800`, `#795548`, etc.) and distinct outlines. They render with high contrast and complete legibility against dark surfaces (`#1C142A`).
  - **Fallback Box (Line 280):** The generic fallback placeholder has hardcoded `bg-gray-100 border-gray-300 text-gray-600`. Replace with `bg-surface-secondary border-control-border text-text-muted`.
- **Reaction Picker (`ReactionPicker.tsx`):**
  - Popover menu must use `bg-surface-secondary border border-border shadow-xl`.
  - Active reaction badges on messages must use `bg-accent-soft text-accent border border-accent/30` instead of hardcoded lavender.

### 6.4 Form Inputs and Interactive Controls
- **Form Controls:** Text inputs, textareas, selects, and checkboxes must use:
  - Background: `bg-surface`
  - Text: `text-text`
  - Placeholder: `placeholder:text-text-subtle`
  - Border: `border-control-border`
  - Focus Ring: `focus:ring-2 focus:ring-focus focus:outline-none`
- **Disabled State:** Must use `bg-disabled-surface text-disabled-text cursor-not-allowed`. Avoid opacity cuts (e.g. `opacity-50`) that drop text contrast below 4.5:1.
- **Autofill Compatibility:**
  ```css
  input:-webkit-autofill,
  input:-webkit-autofill:hover,
  input:-webkit-autofill:focus {
    -webkit-text-fill-color: var(--text);
    -webkit-box-shadow: 0 0 0px 1000px var(--surface) inset;
    transition: background-color 5000s ease-in-out 0s;
  }
  ```
- **Native Color-Scheme:** Setting `color-scheme: dark` on `:root[data-theme="dark"]` guarantees native dropdown menus (`<select>`), date pickers, and checkboxes automatically inherit dark rendering from the operating system browser engine.

### 6.5 Semantic Feedback Banners
- Success, warning, error, and informational messages must maintain distinct chromatic identity. They must **not** all collapse into violet.
  - **Success:** Dark green background (`#132B1E`), border (`#22543D`), text (`#4ADE80`).
  - **Warning:** Dark amber background (`#2C1E0A`), border (`#593F0F`), text (`#FBBF24`).
  - **Error:** Dark red background (`#2D1317`), border (`#5E222A`), text (`#F87171`).
  - **Info:** Dark blue background (`#122340`), border (`#20437A`), text (`#60A5FA`).

## 9. Unresolved Issues Requiring an Owner Decision

During the direct source inspection, three minor design questions were identified. None of them block the core dark mode implementation, but they should be reviewed by the owner:

1. **Theme Selector Presentation in Desktop Sidebar:**  
   - *Option A (Recommended):* A compact 3-way segmented icon button (`[ ☀️ Light | 🌙 Dark | 💻 System ]`) in Region 3 of `SidebarNav.tsx` immediately above the Logout button.
