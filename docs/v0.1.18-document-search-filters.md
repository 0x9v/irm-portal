# Task 0.1.18 — Module Document Search and Filters

**Acceptance status: partial.** Backend/API tests and frontend static/build checks passed. Mocked browser interaction tests are implemented but blocked before execution by the environment’s Chromium sandbox startup failure.

## Existing contract and visibility

The in-module list is `GET /api/v1/communities/{community_slug}/modules/{module_slug}/documents`, implemented in `backend/app/api/v1/endpoints/documents.py` and `backend/app/services/document.py`. It requires an authenticated user, resolves the module inside the requested community, returns a simple array of `DocumentResponse`, includes only `APPROVED` records, and orders by `created_at DESC`. It had no search, pagination, count, or cursor parameters. The response continues to expose only its existing safe metadata fields.

`DocumentType` values are `COURSE`, `TD`, `TP`, `EXAM`, `SOLUTION`, `OTHER`; `DocumentSource` values are `OFFICIAL`, `STUDENT` (`backend/app/models/document.py`). Existing browsing tests confirm guests receive 401, registered non-members and pending members can list approved documents, and active members, Moderators, and Delegates can list them. Pending and rejected documents are excluded for every listing caller. The uploader has no extra visibility into pending/rejected documents through this list. Detail/download routes also require authentication and approved status. No pagination means hidden rows cannot leak through totals, cursors, or page boundaries; those response fields do not exist.

The frontend listing is the module detail page at `frontend/src/app/communities/irm/modules/[moduleSlug]/page.tsx`. It uses `fetchApi`, which includes credentials and supports `AbortSignal`; existing list endpoints use the project’s `ApiError` convention. The listing had no URL query-state convention, so filter state remains local to the page.

## Implementation

Changed files:

- `backend/app/api/v1/endpoints/documents.py` — added optional `q`, `type`, and `source` query parameters to the existing route. Invalid enum values use FastAPI’s 422 validation response. A nonblank trimmed query over 100 Unicode code points returns 422.
- `backend/app/services/document.py` — applies title/type/source predicates to the existing module-and-approved query before fetching rows. Title matching uses case-insensitive literal `ILIKE`, escaping backslash, `%`, and `_`; results retain newest-first order.
- `backend/tests/api/v1/test_document_browsing.py` — added API coverage for literal/case-insensitive/trimmed title search, whitespace-only search, each enum value, combined AND filters, module/status isolation, and invalid values/length.
- `frontend/src/app/communities/irm/modules/[moduleSlug]/page.tsx` — added an explicit Search action, Type and Source selects, Clear filters, filtered-empty state, request-error retry, and request cancellation/generation checks. Search query and filter state are local and retained after failures. Existing cards, upload gate, and reader links remain.
- `frontend/e2e/module-document-search.spec.ts` — added four mocked Playwright cases for request parameters and clearing, empty/error/retry behavior, stale-response protection, and keyboard/theme/320px checks.
- `frontend/playwright.module-document-search.config.ts` — added a focused config with no backend or database hooks.
- `docs/v0.1.18-document-search-filters.md` — this implementation and verification report.

The final optional query contract is:

```text
GET /api/v1/communities/irm/modules/{module_slug}/documents?q={title}&type={type}&source={source}
```

Parameters can be combined and use AND semantics. `q` is trimmed; empty or whitespace-only values act as no search. Matching is case-insensitive literal substring matching on document title only. Maximum nonblank trimmed query length is 100 code points. `type` and `source` must exactly match the enum values above. Example: `?q=linear%20algebra&type=TD&source=OFFICIAL`. Omitting all parameters preserves the original array response and behavior.

The controls use existing semantic surface, text, border, and violet focus/button styles and stack on narrow screens. Changing either select immediately fetches with current applied criteria. Typing does not issue requests; submitting Search trims and applies the draft. Filter changes start a fresh list request (the existing API has no cursor/page state). Clearing restores the authorized unfiltered list. A successful filtered empty response shows “No documents match these filters” with Clear filters; an ordinary empty response keeps “No documents found for this module yet.” Errors show a local retry and retain controls. Query state is not stored in the URL or browser storage.
