## Parallel work and exact gates

Tasks **1, 3 and the presentation/account/D2 portion of 4** can proceed concurrently with separate backend files, PR4 browser fixtures, and read-only browser execution. The standalone PDF return correction in 2 can proceed separately, but **MR5 pending UI waits for MR3**. Run only one production build in a shared frontend workspace at a time; an owner using a shared server coordinates its rebuild with browser runners. Task 5 follows the actual MR3/MR5 contract. Task 6 can classify paths read-only while these proceed, then makes its final selection after source stabilizes.

**Implementation stop point:** MR3 and MR5 pending review exist, C3/C4/C5 are corrected, and any browser/PG failures demonstrate no remaining code defect in this authorized scope. At that point freeze code and review the commit/push. **Local feature acceptance** additionally needs the focused executed browser/PG and real-backend results. **Deployment readiness** additionally needs the actual application DB upgrade and owner operations in Task 7. A source push is neither browser acceptance nor deployment approval.
